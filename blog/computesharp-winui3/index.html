ComputeSharp: 在 C# 里写 D3D12 compute shader

HLSL 源生成器, Shadertoy 移植坐标坑, SwapChainPanel DPI, HDR 边角. ComputeSharpDemo 三个内置 shader.

ComputeSharp

想法

在 C# 里写 shader, 像写普通方法. ComputeSharp 用源生成器做到: 你写 IComputeShader<T>, 编译期翻译成 HLSL, 跑在 D3D12 compute pipeline.

[ThreadGroupSize(DefaultThreadGroupSizes.X)]
public readonly partial struct ProteanClouds(float time, float2 res, ReadWriteTexture2D<float4> output)
    : IComputeShader
{
    public void Execute()
    {
        float2 uv = (float2)ThreadIds.XY / res;
        // fbm, raymarch, 调色
        output[ThreadIds.XY] = new float4(color, 1f);
    }
}

没 .hlsl, 没运行时字符串拼接, 没手动管 ConstantBuffer 布局. 类型系统直接映射 HLSL. 错了编译期报错, 不是黑屏之后对着像素调试器发呆.

Shadertoy 移植. 三个

移植 Shadertoy 到 Compute Shader 都有坐标坑:

  1. Shadertoy fragCoord 原点在左下, D3D 像素坐标左上 — Y 翻转.
  2. iMouse 语义自己设计映射, compute shader 没内建输入状态.
  3. iChannel 纹理要么自己生成要么替换成程序化噪声.

第二个大坑是 Apple Music 风格背景. 原版 (Lyricify-Backgrounds) 是像素 shader 里做 UV 弯曲 (pinch mesh), 但 ComputeSharp 只有 compute shader — 没插值器帮你做 UV 逆变换.

解法: 对每个像素做牛顿迭代求逆变换. 把正向 pinch 当成方程, 迭代解出”这个像素来自哪个 UV”. 顺便实现 77-tap 可分离高斯模糊.

SwapChainPanel DPI

WinUI 3 的 SwapChainPanel 有 winui#8219: DPI 变化时它给的尺寸是 DIP 而不是物理像素.

方案: 维护双份尺寸. 物理像素用于 swap chain 创建和 shader dispatch, DIP 用于布局. 另加一个 500ms 节流的兜底定时器轮询 DPI 变化 — 单一事件在某些显示器热插拔时序下会漏.

HDR. 比想象碎

80% 时间花在 20% 边角:

  • DisplayInformation (WinRT) 和 DXGI output 查询各说各话. 交叉验证.
  • 窗口跨显示器拖动重新评估.
  • Windows 设置里开关 HDR 时, 事件不一定及时. 事件 + 兜底轮询双保险.

输出侧: FP16 swap chain, 色彩空间 (scRGB vs HDR10), SDR 白电平映射. 后来这套经验直接喂给了 DXRDemo 的 HDR10 输出.

插件目录

每个 shader 一个入口类, 注册进 catalog. 新增 shader 大约动 3 个文件, 不碰主窗口.

内置:

  1. Protean Clouds — nimitz 体积云 raymarching, CC BY-NC-SA 3.0.
  2. Ray Trace — 蒙特卡洛路径追踪. 可调弹射次数, 时域累积或 RELAX 降噪.
  3. Apple Music Inspired — 牛顿迭代逆变换版.
