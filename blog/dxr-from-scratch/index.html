从零实现 DXR 路径追踪：雨后便利店的两百万个三角形

不用现成渲染器，在 WinUI 3 里手搓 DXR 1.2 管线——glTF 加载、GGX + MIS、七层嵌套玻璃、NRD 降噪、DLSS/FSR/XeSS 与 HDR10。

图形学DXR路径追踪.NET

DXRDemo 的默认场景叫「雨后便利店」：Blender 里建的模型，约 200 万三角形、3200 个实例、24 种材质、8 盏灯。选这个场景不是为了好看（虽然确实好看），而是因为它同时踩中了路径追踪所有难啃的部分：发光字、湿地面反射、货架上的玻璃瓶。

这篇文章过一遍从零手搓 DXR 管线的路线图。「从零」的意思是：基于 Vortice.Direct3D12 手写绑定，不用现成的渲染框架。

管线骨架

D3D12 的显式 API 在 raytracing 上的复杂度大概是光栅化的三倍。你需要搭的积木：

  • BLAS / TLAS：底层加速结构（每网格一份）+ 顶层加速结构（每实例一份变换）。BLAS 构建Tips：静态场景可以 PREFER_FAST_TRACE 一次建好不再碰。
  • Shader binding table (SBT)：把材质参数和 HLSL 函数绑到射线组上。每个实例 × 每个 hit group 一条记录，布局对齐（8/16 字节）错一点就是驱动层的玄学崩溃。
  • 根签名分治：全局资源（TLAS、输出纹理）走全局根签名，材质局部数据走 SBT 局部根签名。

shader 侧直接上 SM 6.9 / DXR 1.2（DispatchRays 的新特性），驱动不支持时自动降级 lib_6_5，有 SER（shader execution reordering）就用——玻璃多的场景 SER 的收益肉眼可见。

glTF：看着简单，细节要命

用 SharpGLTF 加载 glTF 2.0：节点层级、PBR metallic-roughness、贴图、KHR_punctual_lights 扩展。真正费时间的是坐标系（glTF 右手 Y-up）、切线空间重建、以及索引/顶点格式到 GPU 结构体的逐字节对齐。

材质：GGX + MIS + 一座玻璃山

核心积分器是标准的：GGX 微表面 BRDF + 多重重要性采样 (MIS)——BSDF 采样和光源采样各出一部分样本，按幂权重合并，方差降得比实现成本快。

最花心思的是玻璃。完整实现了 transmission / IOR / 体积材质：

  • Snell 折射 + 全内反射 (TIR)——出水进入空气时超过临界角的那束光必须正确处理；
  • Beer-Lambert 吸收——光在介质内按距离指数衰减，颜色由此而来；
  • 嵌套介电质最多七层——货架上一排酒瓶叠着看过去就是这个场景。

调试玻璃的方式很原始但有效：2 SPP 输出对着 512 SPP 参考图算 RMSE，回归测试套件里这一项在重构后把误差降了约 63%。

降噪：NRD RELAX

2 SPP 的原始噪声没法看，接 NVIDIA NRD 4.17 的 RELAX（diffuse + specular 双通道）。NDK 是 native C++ 的，中间架了一层 C++/CLI 风格的桥接。NRD 的输入要求很严格：world-space normal、motion vector、view depth、roughness，一个不对就出现鬼影或色偏。时域累积作为无 NRD 硬件的退路也实现了。

超分：三个都要

DLSS SR、DLSS Ray Reconstruction、FSR 3.1、XeSS 全部接入，外加一个统一的 1–100% 渲染比例滑杆。动机很实际：不同机器的硬件联盟不同，统一抽象层让「渲染分辨率」和「显示分辨率」彻底解耦。80 种上采样 × 降噪 × HDR 的组合进了诊断套件自动跑——这一步救过好几次驱动更新引入的回归。

HDR10 与落日余晖

显示侧支持 HDR10 输出（SDR 自动回退）。HDR 下的路径追踪是真正的甜点：灯箱的亮度不用压进 sRGB 的笼子里，湿地面反射的高光有真实的物理亮度。WinUI 3 的 Mica 背景和设置窗口（F1）这些 UX 细节也全配齐了——渲染 demo 也要有尊严。

已知限制

诚实清单：静态场景（实例不能动）、不支持 Draco/KTX2 压缩、纹理视图上限 1024、还没有 ReSTIR 和 HDRI 环境。路还长，但两百万三角形已经在 60fps 了。

完整源码、构建说明和诊断套件都在仓库里。如果你也在 .NET 里折腾 DXR，希望这堆踩坑记录能帮你省几个晚上。
