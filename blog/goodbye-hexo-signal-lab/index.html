从 Hexo 迁到 Astro: 一个博客的简化

为什么换掉 Hexo, Astro 的 Content Collections, 字体本地打包, 部署通道.

Hexo → Astro

为什么走

Hexo 没做错. 它只是不属于我:

  • 主题的诅咒. Volantis/Landscape 都是好主题. 但”换主题 = 换博客” 的模型意味着外观永远在别人的审美体系里打转.
  • 构建模型的年代感. 整站 db.json, 生成器插件满天飞, 主题 EJS 模板继承链.
  • 我写的 C# 项目里 GC 停顿都要锱铢必较. 没理由容忍自己博客跑在”默认主题 + 三十个插件”上.

核心诉求就三条: Markdown 写作, 静态输出到 GitHub Pages, 每个像素自己说了算.

选型

  • Hugo: Go 模板快. 定制体验同 Hexo 一个流派.
  • Next.js: 为一个博客引入 React 运行时. 杀鸡用牛刀.
  • Astro: Content Collections + 默认零 JS + 组件即文件. 选它.

Content Collections: src/content/blog/ 丢 .md, frontmatter zod schema 校验. 错了直接构建失败. 很 native 开发者的口味.

默认零 JS: 页面纯静态 HTML, JS 只出现在我手写的地方. 这博客全部运行时 JS 没有 — 没有 shader, 没有频谱, 没有动画. 加起来 0 KB.

Shiki 高亮内置, ayu-dark 顺手. 字体走 fontsource 本地打包 (JetBrains Mono / Noto Sans SC / Space Grotesk 都不需要), 不依赖 Google Fonts.

部署

沿用 Hexo 通道: 本地构建 dist/, 推送到 GitHub Pages 服务的分支:

npm run deploy    # astro build + push dist → my-blog repo main

写作:

src/content/blog/foo.md
---
title: 标题
description: 摘要
pubDate: 2026-10-03
tags: ['audio']
---
正文

npm run dev 预览, npm run deploy 发布.
