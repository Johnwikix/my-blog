告别 Hexo：从零造一个「信号实验室」

为什么放弃 Hexo，用 Astro 从零重建这个博客——设计思路、GLSL 星云背景、伪 FFT 频谱，以及一条命令的部署流。

博客AstroWeb设计

你正在看的这个站，是我在一个下午从零造出来的。它替换掉了服役多时的 Hexo 博客。这篇日志记录为什么走、怎么建的，以及那些「设计师朋友看了会沉默」的个人趣味。

为什么离开 Hexo

Hexo 没做错什么，它只是不属于我：

  • 主题的诅咒。Volantis/Landscape 都是好主题，但「换主题 = 换博客」的模型意味着外观永远在别人的审美体系里打转。我想要的每一个像素——从字距到导航条上那个 REC 呼吸灯——都得跟主题的 CSS 体系搏斗。
  • 构建模型的年代感。整站数据库 db.json、生成器插件满天飞、主题 EJS 模板继承链。改一处样式，心智负担在三套约定里切换。
  • 我写的 C# 项目里连 GC 停顿都要锱铢必较，没有理由容忍自己的博客跑在「默认主题 + 三十个插件」上。

核心诉求其实只有三条：Markdown 写作、静态输出到 GitHub Pages、每个像素自己说了算。

选型：Astro

评估了 Hugo（Go 模板，快，但定制体验同 Hexo 一个流派）、Next.js（为一个博客引入 React 运行时，杀鸡用牛刀）之后选了 Astro：

  • Content Collections：src/content/blog/ 里丢 .md 文件，frontmatter 有 zod schema 校验，slug、日期、标签类型错了直接构建失败——这很 native 开发者的口味；
  • 默认零 JS：页面是纯静态 HTML，JS 只出现在我手写的地方。这个博客全部运行时 JS 只有两块：shader 和频谱，加起来不到 8KB；
  • 组件即文件：.astro 单文件组件，模板 + 样式作用域隔离，没有一个全局 CSS 类需要「覆盖主题默认值」。

Shiki 高亮内置，ayu-dark 和配色刚好一组。字体走 @fontsource 本地打包（Space Grotesk / Noto Sans SC / JetBrains Mono），不依赖 Google Fonts——国内访问的痛点懂的都懂。

设计：信号实验室

我给自己的命题是：这个博客看起来应该像谁写的？ 答案是——像我的 GitHub 主页写的：一个在 Windows 上折腾音频和 GPU 的人。所以整站的概念定为「信号实验室」：

  • 首页背景是一片实时渲染的 GLSL 星云——WebGL fragment shader，fbm 域扭曲噪声，青→紫的配色。它是我 ComputeSharpDemo 里那些体积云 shader 的 WebGL 方言版，鼠标移动会轻微扰动漂移方向。
  • 伪 FFT 频谱条出现在英雄区读数面板和页脚——canvas 2D 画的 42 段假频谱，快攻慢放的包络模拟真实 RMS 表头的坠落感。这是对我播放器频谱可视化的致意。
  • HUD 读数面板：AUDIO 44.1k–768k · DSD512、RENDER DXR 1.2 · 2 SPP——这些数字都是真的，来自我的项目。
  • 页脚有一个真实的 fps 读数，事件总线从 shader 的 rAF 循环里广播出来——一切装饰都必须是真的，这是原则。

性能上做了克制：shader 半分辨率渲染 + 30fps 节流（它是氛围层，不需要吃满 GPU）；prefers-reduced-motion 时频谱静止、shader 换成静态渐变。

部署：一条命令

沿用原来 Hexo 的部署通道——本地构建出 dist/，脚本推到 GitHub Pages 服务的分支：

npm run deploy   # astro build + 推送 dist 到 my-blog 仓库

写作流程则简单到没有仪式感：

# src/content/blog/ 里新建 .md
---
title: 标题
description: 摘要
pubDate: 2026-10-03
tags: ['音频']
---
正文……

npm run dev 本地预览，npm run deploy 发布。仓库里另附了 GitHub Actions 工作流，想切全自动构建部署也只是一次开关的事。

旧文与新起点

旧博客只有一篇默认的 Hello World——就不搬运了，让它体面地留在历史里。接下来的日志会聚焦三个方向：音频管线（播放器架构的深水区）、渲染（DXR/ComputeSharp 的踩坑实录）、以及 .NET native 开发的日常。

欢迎来到信号实验室。示波器已上电。
