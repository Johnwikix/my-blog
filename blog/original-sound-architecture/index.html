把音频管线拆进独立进程：原音 HQ 播放器的架构决策

为什么一个音乐播放器要把自己劈成两个进程——聊聊原音 HQ 播放器的独立音频进程、共享内存 IPC、WASAPI 独占模式与 float64 DSP 链。

音频WinUI 3.NET架构

写一个能出声的播放器很容易，写一个敢自称 HQ 的播放器很难。这篇文章记录「原音 HQ 播放器」到目前为止最重要的一个架构决策：把整条音频管线从主进程里搬出去，塞进一个独立的 NativeAOT 进程。

问题从哪来

播放器的天敌不是功能复杂度，而是「卡」。UI 掉帧、GC 停顿、窗口拖动、列表虚拟化——任何一个都可能在某个瞬间抢走 CPU 时间片。对普通应用这只是掉个帧；对独占模式的音频输出，这意味着缓冲区欠载（buffer underrun），直接可闻的爆音。

.NET 的托管环境放大了这个问题：Gen2 GC 一次 STW 停顿完全可以超过一个音频周期的预算。你可以调 GCServer、可以 GCConserveMemory、可以把回调钉在专用线程上，但只要音频代码和 UI 跑在同一个进程里，你就永远在和运行时抢时间。

所以结论其实很直接：

音频 deserves 一个不被打扰的世界。

拆分方案

最终的结构是这样的：

┌─────────────────────────┐        ┌──────────────────────────┐
│  主进程 (WinUI 3)        │        │  AudioPlayer 进程         │
│                         │        │  (NativeAOT 单文件)        │
│  UI / MVVM / 曲库 SQLite │◄──────►│  FFmpeg 解码              │
│  频谱 / 歌词 / shader 背景 │ shared │  WASAPI 独占 / ASIO       │
│                         │ memory │  DSD DoP / Native         │
│                         │  ring  │  DSP: EQ / 卷积 / R128    │
└─────────────────────────┘        └──────────────────────────┘

几个关键点：

  • 音频进程用 NativeAOT 编译成单文件 exe。没有 JIT、没有 GC，启动即稳定。它只做一件事：从共享内存取指令、解码、过 DSP、喂给声卡。
  • IPC 走共享内存环形缓冲，不走命名管道序列化大块数据。控制指令和 PCM 数据分通道，进程间通信的延迟被压在微秒级。
  • 主进程崩了音乐不停。UI 崩溃、调试重启，声音照常播放——这大概是这个设计最奢侈的副产品。

WASAPI 独占模式：值得吗

值得。独占模式下应用直接面对声卡硬件缓冲，绕过 Windows 的混音器（以及它隐式的重采样和音量处理）。配合同格式无缝切换（zero-gap），连续播放整张专辑时听不到任何格式转换的接缝。

DSD 是另一条战线。DoP（DSD over PCM）把 DSD 流打包进 PCM 帧伪装传输，兼容性好；Native DSD 则需要 ASIO 通道直接吐原始比特流，还要处理 LSB1/MSB1/NER8 这些打包格式。两种我们都做了，因为一旦你走到 DSD256/512，每一个重采样步骤都是亵渎。

DSP：float64 不是玄学

原音的 DSP 链跑在 float64 精度上：10 段参数 EQ、卷积校正（曲线编辑器或直接导入 WAV 脉冲响应，可绑定到输出设备）、EBU R128 响度归一化、crossfeed。

用 float64 的理由很实在：级联滤波器的累积误差是真实存在的。单级 EQ 在 float32 下人耳不可闻，但五六级处理串下来、再经过卷积这种乘加密集的运算，低位噪声会开始积累。位深既然都保到 DSD512 了，DSP 中间精度没理由偷懒。

卷积校正是最「发烧」的一个功能——导入你的耳机/房间测量脉冲响应，播放时实时做频域卷积修正。FFT 分块卷积的开销控制是难点，但这是另一个话题了。

代价

诚实地说，这个架构的代价不小：

  • 两套工程要维护。音频进程是 C++ 风格的 interop 代码（FFmpeg.AutoGen + WASAPI/ASIO 手写 P/Invoke），和主进程的 C# MVVM 世界完全是两种写法。
  • 调试复杂度翻倍。跨进程断点、共享内存的竞态、崩溃转储要分别分析。
  • 看门狗逻辑（设备热插拔、独占模式被抢占后的自动恢复）写起来琐碎，但缺了它用户体验直接崩塌。

但每次看到任务管理器里那个 2MB 的音频进程稳定跑着 3ms 音频周期、而 UI 进程随便怎么折腾都影响不到它的时候，我觉得这笔账是划算的。

项目完全开源（AGPL-3.0）：Original-Sound-HQ-Player。从源码构建没有任何功能限制——这也是开源给发烧友的承诺。
