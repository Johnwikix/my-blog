Original-Sound-HQ-Player: 独立音频进程

把整条音频管线从主进程拆出。 共享内存 IPC, NativeAOT, WASAPI exclusive, float64 DSP 链。

独立音频进程

问题

独占 WASAPI 下, 一个 3ms 的 Gen2 STW 停顿会被听成爆音. UI 线程、虚拟列表、shader 背景——都和音频回调抢同一颗 CPU.

结构

┌─────────────────────────┐        ┌──────────────────────────┐
│  main (WinUI 3)         │        │  AudioPlayer (NativeAOT) │
│  UI / MVVM / SQLite     │◄──────►│  FFmpeg + WASAPI/ASIO    │
│  spectrum / lyrics      │ shared │  EQ / convolution / R128 │
└─────────────────────────┘ memory └──────────────────────────┘
  • 音频进程 NativeAOT 单文件 exe, 没 JIT 也没 GC.
  • IPC 用共享内存环形缓冲, 不走命名管道.
  • 主进程崩了音频不停.

WASAPI exclusive. DSD

exclusive 下应用直对硬件缓冲, 绕过 Windows 混音器 (隐式重采样 + 音量处理). 同格式 zero-gap 切换.

DSD 两套:

  • DoP: DSD 打包成 PCM 帧, 兼容性好.
  • Native: ASIO 直吐原始比特, LSB1/MSB1/NER8 都要处理.

DSP. float64

10 段参数 EQ + 卷积 (曲线编辑器或 WAV 脉冲响应导入) + EBU R128 + crossfeed.

float64 不是玄学. 五六级滤波器 + 卷积的乘加, float32 下低位噪声会开始积累. 解放源 bit depth 到 DSD512 了, DSP 中间精度没理由偷懒.

代价

  • 两套工程. 音频进程是 C++ 风的 interop, 主进程 C# MVVM. 两种写法.
  • 调试复杂度 ×2. 跨进程断点、共享内存竞态、崩溃转储分开看.
  • 看门狗. 设备热插拔、独占被抢占自动恢复. 琐碎但缺了不行.

但每次看到任务管理器里那个 2MB 的音频进程稳定跑 3ms 音频周期, UI 进程随便折腾它都不抖, 这账就值.
